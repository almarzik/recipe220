# Станция рецептов — SS14

Откройте **index.html** двойным щелчком. Сайт работает локально, без сервера, регистрации, внешних шрифтов и подключения к интернету. Готовая база уже включена в `recipes.js`.

Если предпочитаете запуск по HTTP: установите Node.js 22 или новее, выполните `node server.cjs` в этой папке и откройте http://127.0.0.1:4173. Сервер слушает только ваш компьютер. Сохранения для адреса HTTP и для файла независимы.

## Как пользоваться

- Выберите категорию: химия, кулинария или барменство. Дополнительный фильтр разделяет рецепты по назначению.
- Ищите по русскому названию, ингредиенту или ID прототипа. Клавиша `/` переводит фокус в поиск.
- Нажмите **+ На поле**, чтобы добавить карточку в верхнюю рабочую зону.
- В **Кулинарии** кнопка **Составить меню из 10 блюд** подбирает разные готовые блюда из нескольких разделов и размещает их карточки на поле. Уже добавленные блюда пропускаются. Заготовки, нарезка, медицинские и секретные рецепты не входят в подбор. Это случайное меню из каталога, без проверки запасов ингредиентов в раунде; поиск и фильтр раздела на подбор не влияют.
- Карточки компактные: состав виден сразу, длинный список ингредиентов прокручивается внутри. Этапы химических реакций, инструкции игрока и примечания раскрываются по клику.
- В кулинарии у блюд и ингредиентов есть миниатюры из игровых спрайтов. Для жидких реагентов без отдельного спрайта отображается капля их цвета.
- Нажмите **название кулинарного рецепта** в каталоге или на рабочем поле, чтобы открыть отдельный просмотр без добавления карточки. В нём стрелка у ингредиента открывает его рецепт, кнопка «Назад» возвращает к предыдущему. Закрыть можно крестиком, клавишей Escape или кликом вне окна.
- Перетаскивайте карточки за шапку мышью или пальцем. У сфокусированной шапки работают стрелки, с Shift — увеличенный шаг.
- Нажмите **[+]** рядом с составным ингредиентом: его рецепт появится справа. Если способов несколько, сайт предложит выбрать. Линия связывает карточки. Повторное нажатие для того же способа возвращает к уже добавленной карточке.
- В химии составные реагенты раскрываются **автоматически**, без [+]. Сверху указан общий список исходных веществ с пометками, для какого промежуточного реагента они нужны; ниже — этапы синтеза и финальное смешивание с температурами. Одинаковые расходуемые вещества суммируются. Катализаторы указаны отдельно, их запас рассчитан на повторное использование между этапами. Реагенты штатного химраздатчика считаются исходными. При нескольких путях используется рецепт с совпадающим ID реагента, иначе способ с меньшим числом ингредиентов; выбранный способ подписан. Циклические цепочки останавливаются с пояснением.
- Укажите **Нужно на выходе**: количество готового продукта, а не множитель ингредиентов. Например, 200 ед. напитка или химиката, 5 готовых булочек. Ингредиенты рассчитываются по отношению нужного выхода к выходу базового рецепта. Для нескольких продуктов можно выбрать, по какому рассчитывать объём; остальные продукты отображаются дополнительно.
- Для нарезки, предметных и других неделимых рецептов используются целые партии. Например, при запросе 7 кусочков и выходе 3 из одной заготовки потребуется 3 заготовки: сайт покажет фактический выход 9 и пояснение. Катализаторы не расходуются и не умножаются.
- При добавлении подрецепта его количество рассчитывается по требуемому ингредиенту и выходу. Изменение нужного выхода родительского рецепта пересчитывает связанные карточки. В окне просмотра также можно рассчитать нужный выход; это не меняет карточки рабочего поля.
- **Расставить** укладывает карточки рядами. Поле растягивается за нижний край без верхнего ограничения высоты. Можно задать высоту числом, например **2000 px**, под полем; размер сохраняется в браузере. «Обычный размер» возвращает 475 px.
- **Скрыть поле / Показать поле** сохраняет карточки и отметки. При прокрутке закреплена только компактная панель с названием, количеством карточек и кнопкой скрытия. Само поле любой высоты и кнопки расстановки прокручиваются вместе со страницей. **Показать поле** раскрывает его и возвращает к нему; кнопка **Рабочая область** в верхней панели позволяет вернуться и к уже открытому полю. Добавление рецептов сохраняет свёрнутое состояние и не прокручивает каталог.
- Положение карточек, количества и отметки автоматически сохраняются в localStorage браузера. Очистка данных браузера удаляет это сохранение.

## Актуальность и происхождение

### От Игроков

Вкладка **От Игроков** содержит структурированную методичку **Травницы Луны**: закупку реагентов, этапы варки, советы и необязательные рецепты. Доступны оглавление, поиск, раскрываемые разделы и отметки выполнения, которые сохраняются отдельно от рабочего поля.

Авторские количества, последовательность и нумерация сохранены; методичка не подменяет базу прототипов. **«Партия автора на поле»** добавляет отдельную карточку с ингредиентами и количествами из выбранного этапа, заявленным автором выходом и пошаговой инструкцией. Ингредиенты и шаги отмечаются независимо; карточку можно перемещать и сохранять. Разные варианты одного лекарства в разных этапах не объединяются.

Карточка методички использует фиксированную авторскую партию: диапазоны и неясные количества не пересчитываются автоматически. **«Рецепт сборки»** открывает обычный калькулятор для другого выхода. В исходнике есть округления и неоднозначные места; они не исправляются автоматически. Оригинал без изменений доступен по кнопке скачивания и лежит в `player-guides/chemistry-original.txt`. Составы авторских партий хранятся в `player-batches.cjs`.

Для повторной структуризации локальной копии выполните `node build-player-guide.cjs`: он создаст `player-guides.js`. Обновление игровой базы не перезаписывает методичку.

### Ботаника

Вкладка **Ботаника** в верхней панели содержит отдельные разделы:

- **Растения и цепочки** — все виды из seed-прототипов, переходы `mutationPrototypes`, цепочки по шагам, возможные развилки, урожай и его базовый состав. Поиск понимает «мясная пшеница». Если виды могут мутировать друг в друга, показаны короткие пути с готовых семян предшествующего вида. Наличие семян в конкретном раунде не гарантируется.
- **Реагенты для растений** — все реагенты с `plantMetabolism`, их эффекты, вероятности и условия из сборки. Здесь есть нестабильный мутаген, криоксадон, удобрения и прочие средства. Можно посмотреть синтез, рассчитать нужный запас и добавить химический рецепт на рабочее поле.
- **Случайные мутации** — полный активный список свойств, базовые коэффициенты вероятностей и случайный пул реагентов урожая. Дозировка не гарантирует нужную мутацию. Криоксадон может оказаться в случайном составе плодов; как средство ухода он лечит, снижает токсины и омолаживает растение.

Данные извлекает `build-botany.cjs` из тех же локальных прототипов. Порядок обработки, вероятности и специальные эффекты сверены с `Content.Server/Botany` и `Content.Server/EntityEffects/Effects/Botany`. Рецепт запаса реагента не является указанием вылить весь рассчитанный объём в растение.

Источник — **локальные файлы этой сборки**, включая SS220 и Corvax, а не сторонняя вики. Снимок отражает содержимое рабочего дерева в момент запуска импортера; версия Git и дата показаны внизу сайта. После обновления игры запустите **update-data.cmd**, затем перезагрузите страницу. Для обновления нужен Node.js и пакет `yaml`; для просмотра они не требуются.

Импортер читает `Resources/Prototypes` и локализацию `Resources/Locale` только для чтения. Поддерживаются:

- реакции, продукты, создание предметов, катализаторы, температуры и требуемые способы смешивания;
- рецепты микроволновки, включая секретные рецепты с отдельной пометкой;
- нарезка и кухонный комбайн, с наследованием компонентов прототипов;
- графы приготовления еды, раскатывание и нагрев, в том числе промежуточные узлы;
- отжим соков и измельчение растений: отображается базовый выход, в игре он может меняться;
- дополнительные эффекты реакций доступны в раскрываемом источнике на карточке.

База описывает рецепты в прототипах: доступность редких, событийных и административных ингредиентов зависит от раунда. Произвольная сборка блюд через foodSequence без фиксированного состава не представлена как фиксированный рецепт. Импортер не симулирует эффекты, побочные реакции и изменения состава предметов во время раунда. Каждый рецепт содержит исходный путь и ID для проверки. Извлечённые данные сохраняют условия лицензирования исходного проекта; см. `../LICENSE.TXT`, `../CLA.txt` и заголовки файлов-источников.

## Разработка

### Раздел СБ

Во вкладке «СБ» рабочая область и её панель скрыты, карточки остальных разделов сохраняются. Таблица содержит 32 статьи из редакции 14940 Космического закона SS220 (правка от 6 сентября 2026). Доступны поиск, фильтр тяжести, учебные примеры при наведении / фокусе и полные пояснения по клику. Галочки выбирают статьи для дела.

Форма создаёт редактируемый проект официального предупреждения для 1XX либо рапорта для более тяжких статей. Проверяются одинаковые последние две цифры кодов и несовместимость 309 с 102 / 202 / 302. Остальные ограничения совокупности требуют проверки пользователем; итоговый срок не назначается автоматически. Самооборона / крайняя необходимость передаются на рассмотрение, предупреждение до проверки не предлагается. Копирование работает через буфер обмена, с выделением текста как запасным вариантом. Данные дела хранятся только в памяти вкладки до перезагрузки.

Источник: https://wiki14.ss220.club/wiki/Космический_Закон. Авторы SS220 SS14 WIKI; текст и адаптированные материалы КЗ (включая учебные примеры) — **CC BY-NC-SA 4.0**: https://creativecommons.org/licenses/by-nc-sa/4.0/. Тексты статей сохранены, компоновка изменена, примеры и форма добавлены. Копия статьи сохранена в `security-source.html` для воспроизводимости; сервер её не раздаёт. `node build-security.cjs` формирует `security-data.js` из этой копии, без обращения в сеть. Для обновления сначала загрузите свежую статью и проверьте изменения кодификации, исключений и примеров. Перезагрузка сайта сама по себе не обновляет редакцию КЗ.

### Раздел «Учёный»

Справочник артефактов без рабочего поля: **26 стимулов и 68 эффектов**, включая варианты вне стандартных таблиц. По умолчанию отображаются 25 стимулов и 60 эффектов из стандартной генерации (в том числе эффекты только для ручных артефактов). Поиск работает по русским подсказкам, ID, способам воздействия, реагентам и создаваемым объектам. В каждой раскрывающейся карточке есть пояснение и исходные параметры прототипа. Составы пены и луж показывают возможные варианты, а не обещание получить все вещества сразу.

Есть памятка по дереву узлов, окну разблокировки и частым ошибкам; заметки исследователя сохраняются в `ss14-scientist-notes` в браузере. Источники — `Resources/Prototypes/XenoArch/{triggers,effects}.yml`, русские локализации и системы `Content.Shared/Xenoarchaeology/Artifact` / `Content.Server/Xenoarchaeology/Artifact`. Пороги, способы проверки и исключения сверены с кодом этой сборки. Нестандартные администраторские изменения конкретного артефакта справочник не предсказывает.

`npm run build:scientist` обновляет `scientist-data.js` из локальных файлов; сначала обновите `recipes.js`, если менялись названия реагентов. Общий `npm run build` выполняет обе сборки. При изменении механики XAT/XAE пересмотрите пояснения в `build-scientist.cjs`: текстовые инструкции и базовые значения из C# не обновляются автоматически.

### Запуск и проверки

Внутри «Учёного» есть переключатель **«Артефакты / Аномалии»**. Аномалистика включает 18 пространственных вариантов из `anomalies.yml` (в том числе семь каменных разновидностей и специальный подарочный вариант), 21 поведение из `behaviours.yml`, инструкции по поиску, сосуду, частицам, импульсам, завершению работы и ядрам. Инъекции внутренних аномалий относятся к отдельной механике и в этот каталог пространственных типов не включены.

Помощник принимает состояние и роли частиц из сканера. Роли не привязаны к фиксированным буквам; неизвестные и противоречивые показания не превращаются в совет стрелять случайным типом. Помощник не подключён к игре, не рассчитывает гарантированное число выстрелов и не сохраняет показания между перезагрузками. Переключение внутренних вкладок сохраняет введённый поиск артефактов и заметки.

`npm run build:anomalies` обновляет `anomalies-data.js` из локальных прототипов с учётом наследования. Общая сборка также запускает этот этап. После изменения C#-механик пересмотрите инструкции и помощник в `anomalies.js`, а также пояснения видов в `build-anomalies.cjs`.

Новые карточки размещаются слева направо с переносом на следующую строку по ширине рабочего поля. Положение уже расставленных карточек сохраняется.

В разделе «Кулинария», у шефа, раскройте «Меню из моих запасов». Список разделён на ШефВенд, животных, ботанику и другие продукты. «Отметить ШефВенд» выбирает обычный ассортимент `ChefvendInventory`, без контрабанды, и сохраняет уже отмеченный урожай. Животных отмечайте отдельно: их наличие зависит от карты. Коза даёт `MilkGoat` и после разделки `FoodMeat`, свинья — `FoodMeatBacon`; козье молоко не заменяет `Milk`. Для коробки животных кубиков мясо автоматически не предполагается.

Подбор проверяет выбранные запасы и составные ингредиенты, соки и нарезку. Только вода и кухонная посуда считаются доступными автоматически. Выбор сохраняется в браузере, количество запасов не рассчитывается. Добавляется до 10 новых подходящих блюд; если их меньше, добавляются только найденные. Обычная кнопка случайного меню из 10 блюд работает независимо от запасов. Соответствие списка ассортименту ШефВенда проверяется тестом по локальному YAML; при изменении прототипов обновите `chefStock` в `chef-menu.js`.

```sh
npm ci
npm run build
npm test
npm start
```

`build-data.cjs` формирует `recipes.js` и `data-summary.json`, а `build-thumbnails.cjs` копирует используемые PNG в `assets`. Миниатюры используют первый кадр RSI и слои прототипа. Источники, авторство и лицензии спрайтов сохраняются в `assets/credits.json`. При копировании сайта переносите всю папку вместе с `assets`. Интерфейс — обычные HTML, CSS и JavaScript. Тесты проверяют реальную базу и пользовательские сценарии в DOM; они не заменяют визуальную проверку в браузере.

«Инженерия → Атмосия» — справочник без рабочего поля: 9 газов, все 6 активных газовых реакций локальной сборки, оборудование, порядок запуска и устранения проблем. Карточки раскрывают условия, пропорции, шаги и ссылки на исходные файлы. Калькуляторы считают исходную смесь в молях и давление по nRT/V; это не симуляция одновременных реакций и не гарантия выхода фрезона или трития. Проценты смесителя применимы к указанным молярным долям при одинаковых температурах входов.

`npm run build:engineering` обновляет `engineering-data.js` из газовых прототипов, реакций и констант Atmospherics.cs. Пошаговые пояснения и пресеты в `engineering.js` нужно сверять при изменении игровой механики. Закомментированная реакция выпадения луж из водяного пара не включена в активный каталог. При первом добавлении инженерии перезапустите `npm start`, чтобы сервер подхватил новые файлы в списке разрешённых ресурсов.

В «Атмосии» добавлены «Цены и время» и «СМ». Экономика подставляет теоретические количества для шести схем по заданному выходу основного продукта; реальные потери и конкурирующие реакции нужно учитывать вручную. Цены берутся из `pricePerMole`, пользователь может изменить их и добавить расходы. Оценка одной смеси учитывает коэффициент чистоты из `AtmosphereSystem.GetPrice`, а режим отдельных газов предполагает полное разделение. Время считается по приросту отфильтрованного продукта за замер; скорость не считается постоянной характеристикой рецепта.

Помощник СМ принимает абсолютные замеры `секунды; материя; внутренняя энергия`, рассчитывает наклон линейной регрессией по последнему окну и предлагает частичную поправку одинаково настроенной группы эмиттеров. Цель по умолчанию — 100000 материи; центры энергии и добавки от попадания соответствуют локальным SS220-классам. Поправка учитывает текущую кривую выбранной энергетической полосы, а не прыжок к энергии конечной цели. Нет телеметрии, автопилота, полной симуляции газового обмена или гарантии устойчивости. После смены настроек нужно начать новое окно; история сохраняется при переключении вкладок, но не после перезагрузки страницы. Реальные попадания за окно можно указать вместо среднего темпа. При изменении исходного C# нужно сверить формулы `supermatter.js`; основные константы и сценарии проверяются тестами.

После добавления `atmos-economy.js` и `supermatter.js` перезапустите локальный сервер, чтобы обновить его список разрешённых файлов.

Миниатюры атмосии собираются `build-atmos-thumbnails.cjs` при `build:engineering`: канистры всех газов, оборудование, кристалл СМ и эмиттер берутся из локальных прототипов с наследованием Sprite. Используется первый кадр видимых слоёв RSI; PNG копируются в `assets`, а авторство и лицензии — в отдельный `assets/engineering-credits.json`, без перезаписи кредитов кулинарии. Для газа изображается соответствующая канистра; для реакции — её продукт, топливо или оборудование. Все карточки, таблица цен, калькулятор смеси и раздел СМ используют эти миниатюры.

Раздел СМ оформлен как игровой наблюдатель SS220: компоновка `SuperMatterObserverMenu.xaml`, фон #1B1B1E, график сверху слева, показания справа, карта M/E и газовые полосы снизу. `sm-observer.js` добавляет быстрый ввод замеров, переключение графиков и окно эмиттеров с шагами мощности и ползунком. Карта строится по тем же центрам полос и функции повреждения M/E; цвета интерполируются между LightGreen и DarkRed, как GoodBad в PlotColormap.cs. Масштаб адаптирован к пользовательской цели и последнему замеру. Нет автоматической телеметрии: целостность, давление, температура и газы показываются только при ручном вводе, не наследуются от прошлой точки и сбрасываются с новым окном. График целостности не подменяется материей; другие показатели переключаются явно. После добавления файлов `sm-observer.js` и `sm-observer.css` перезапустите сервер сайта.

Химические карточки: новый жидкий рецепт по умолчанию рассчитывается на 200 ед. готового продукта; существующие сохранённые объёмы остаются прежними. Переключатели 50/100/200 и произвольный выход расположены сверху. Вместо раскрытия дерева показаны последовательные реакции: отдельная подготовка, дозы, выход, перенос нужного количества и ссылка на предыдущий шаг. Общий исходный запас свёрнут, чтобы его не принимали за смесь в одном стакане. Выполнение шагов сохраняется; изменение объёма сбрасывает отметки. Название открывает просмотр без добавления карточки. Катализатор не включается в выход продукта, дробные дозы показываются до трёх знаков. Количества вычисляются прежним алгоритмом `WorkbenchChemistry.expand`; карточки еды, напитков и авторских партий используют свои прежние схемы.

Калькулятор смесей теперь принимает итоговое давление в кПа, температуру в K/°C и реальный объём в литрах. Выводит доли смесителя, парциальные давления и накопленное давление при последовательном заполнении изначально пустой ёмкости без реакций при постоянной одинаковой температуре. Настройки давления источников из этой таблицы не выводятся. Для передачи в экономику скрыто рассчитывает моли через PV/RT. Переключение K/°C сохраняет физическую температуру. Отдельный калькулятор нагрева работает через P₂=P₁T₂/T₁, без ввода молей.

Во всём интерфейсе инженерии количества газа теперь выражены в кПа: справочник реакций, газовые карточки, экономика, время и панель СМ. Рецептурные примеры и минимальные запасы приведены к 293,15 K и 1000 л; рабочие температуры реакций указаны отдельно. В экономике пользователь задаёт общие опорные T/V для входа и выхода, стандартные цены за кПа пересчитываются, ручные цены сохраняются. Импорт из калькулятора сохраняет количество газа через приведение к условиям партии. Скорость производства измеряется в кПа/с только при постоянной температуре и объёме; изменение опорных условий сбрасывает замеры времени. Внутренние физические вычисления и исходные данные игры не менялись.
# Калькулятор СБ

Вкладка СБ содержит справочник и отдельную панель расчёта: статьи, выбор срока для 1XX и 3XX, повторные приговоры, пособничество, подтверждённые основания снятия обвинений и общие модификаторы. Панель можно перенести вниз; на узком экране кнопка с итогом ведёт к расчёту. Рабочего поля рецептов в СБ нет. Рапорт свёрнут отдельно и включает актуальный расчёт; изменение условий сбрасывает старый документ.

Источник правил — [Космический закон SS220](https://wiki14.ss220.club/wiki/Космический_Закон), редакция 14940, сверена 21.09.2026. Справочник уже соответствует этой редакции. Сроки из калькулятора Corvax WL не используются.

Сначала применяется предел совокупности (1,5 максимального выбранного срока), затем повышения, затем снижения. Два снижающих коэффициента 0,5 применяются последовательно. Рецидивы учитываются как отдельные повторные приговоры по выбранной статье. Для одновременных рецидива и отказа от сотрудничества доступен выбор порядка: источник явно задаёт только повышения до снижений. Выбранный порядок виден в расшифровке. Для смешения собственных нарушений и пособничества автоматический итог блокируется: в источнике не описано распределение общего предела для такой комбинации.

60 минут и более и пятое нарушение дают отдельный результат «Пермабриг», 5XX — «Высшая мера», без конечного таймера камеры. Подтверждённое основание снятия выбирается отдельно для каждой статьи. Флажок о заявленной самообороне в рапорте требует проверки, а не автоматически снимает обвинения.

В интерфейсе все модификаторы собраны в один блок «Модификаторы» с десятью кнопками: пособничество, директива ЦК, сотрудничество с СБ, контроль разума, угроза заключённому, отказ от сотрудничества, рецидив, самооборона, явка с повинной, крайняя необходимость. Кнопки показывают активное состояние и отключают свой эффект при повторном нажатии. Дополнительные поля открываются в этом же блоке. Рецидив выбирается выпадающим списком для каждой статьи; самооборона и крайняя необходимость могут относиться ко всем статьям или одной выбранной. В карточках статей остаётся только срок. Медпомощь и УДО не входят в выбранный пользователем набор кнопок. Пособничество применяется ко всему выбранному набору статей; случай без обвинений у основного нарушителя имеет отдельный режим на 5 минут. Особые действия включаются в копирование и рапорт. Побег и статус врага корпорации требуют отдельного решения по КЗ.

Проверки: `npm.cmd test` (включая чистые расчёты в `security-test.cjs` и интеграцию интерфейса в `test.cjs`).
